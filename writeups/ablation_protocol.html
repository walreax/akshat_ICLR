Causal Ablation Protocol

The concept metric has no ground truth to correlate against — so correctness has to come from intervention, not correlation. This protocol zeroes and amplifies the exact SAE latent the metric names as responsible for a concept, regenerates, and checks whether the image changes where — and only where — the metric predicted it would.

§1

Why intervention, not correlation

concept_metrics.csv already tells you which latent argmax-fired for a given (concept, block, timestep): a correlational claim — this latent's activation pattern lines up with where the concept sits in the image. That is observation, not mechanism. A latent could line up with a concept's location by coincidence, by confound (e.g. it fires for anything bright in that region), or because it genuinely encodes that concept causally.

The only way to tell those apart without human labels is to intervene: physically remove that latent's contribution to the residual stream mid-generation and see whether the concept's visual signature disappears (necessity), then push the latent harder and see whether it strengthens (sufficiency). If both hold — and a randomly chosen other latent does neither — the metric is measuring a real causal handle on the model, not a spurious spatial coincidence.

§2

The mechanism: decoder-direction patching

Every SAE latent has a fixed direction in the block's residual space — its decoder column. Removing or boosting a latent is just adding a scaled copy of that one column to the block's output tensor, then letting the rest of the forward pass run untouched.

One latent, one direction, one scaled delta — subtracted for necessity, amplified for sufficiency, same seed as baseline.

patch construction · applied inside a forward hook on the target block
def make_patch(sae, latent_idx, activation, mode="ablate", factor=3.0):
    z = sae.encode(activation)                 # (..., d_hidden)
    z_i = z[..., latent_idx].unsqueeze(-1)     # this latent's activation
    d_i = sae.decoder.weight[:, latent_idx]     # (d_in,) fixed direction
    delta = z_i * d_i
    if mode == "ablate":
        return activation - delta
    return activation + (factor - 1) * delta   # mode == "amplify"
§3

Pipeline

Five stages, run per (model, block, timestep, latent, concept) tuple. Stages 1–3 share one seed so the only difference between the three images is the patch.

00
selection

Pick candidate latents from top_concepts_top32.csv

Testing every argmax-selected latent in concept_metrics.csv is wasted effort — most only ever fire once and tell you nothing about reliability. The top-32 file already ranks latents by frequency within each (model, block, timestep); take the top 5 per cell. These are the latents the metric leans on repeatedly, so they're the ones worth a causal claim about.

01
baseline

Generate + capture, unmodified

For each candidate latent, sample 3 concepts (prompt/seed pairs) that actually selected it as argmax at that cell — joining back against concept_metrics.csv. Generate normally, saving the image and the raw block activation at the matching step_index. This is the reference every comparison below is measured against.

02
patch construction

Build the ablate, amplify, and control deltas

From the captured activation: the real latent's ablate-delta and amplify-delta (§2), plus a control delta built the same way from a different latent index — one that never argmax-fired for this concept at this cell. Same construction, unrelated direction.

03
regenerate · necessity regenerate · sufficiency

Re-run with the patch hook active, same seed

Three more generations per concept: ablated (real latent, −Δ), amplified (real latent, +(k−1)Δ), and control-ablated (unrelated latent, same magnitude). The hook only touches the one matching block at the one matching step_index; every other forward pass in the run is untouched, so any change downstream is attributable to that single intervention.

04
scoring

Local vs. global change, real latent vs. control

Score every patched image against its baseline with a perceptual-distance mask centered on the concept's own (centroid_x, centroid_y) — already computed and sitting in concept_metrics.csv. Detailed in §4.

§4

Scoring: specificity, not just difference

Any strong enough patch changes the image somewhere — that alone proves nothing. The claim worth making is narrower and stronger: patching this latent changes the image specifically where the metric said the concept lives, and patching an unrelated latent by the same magnitude does not.

Same magnitude patch, two latents. A real concept latent moves pixels inside its own mask; an unrelated latent moves pixels everywhere a little.

specificity score · per patched image, against its baseline
def specificity(baseline_img, patched_img, cx, cy, concentration, eps=1e-3):
    radius = mask_radius_from_concentration(concentration)
    mask   = gaussian_mask(center=(cx, cy), radius=radius, size=baseline_img.size)
    local  = lpips(baseline_img, patched_img, weight=mask)
    global_ = lpips(baseline_img, patched_img, weight=1 - mask)
    return local / (global_ + eps), local, global_
§5

The actual statistical claim

Every candidate concept produces a paired observation: specificity_real and specificity_control, same image, same patch magnitude, same mask — only the latent identity differs. That pairing is what makes this a clean test: a Wilcoxon signed-rank test on specificity_real − specificity_control across all sampled concepts, one-sided (real > control). Necessity and sufficiency runs are tested separately; both should reject the null.

Report effect size alongside significance — the median of that paired difference, per (model, block, timestep) — since with hundreds of samples even a small, uninteresting effect will be "significant." A large, consistent gap is the actual proof-of-mechanism claim for the paper; the p-value is just the gate.
